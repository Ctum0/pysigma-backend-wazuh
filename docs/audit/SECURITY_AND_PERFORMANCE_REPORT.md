## 1. Security Architecture & Threat Analysis

Because detection backends often process untrusted third-party Sigma rules in automated CI/CD pipelines, detection-as-code repositories, and customer SIEM ingestion pipelines, the backend was audited against common untrusted-data vulnerabilities.

### 1.1 Injection Defenses

| Threat Vector | Attack Mechanism | Implemented Safeguard | Audit Verdict |
| :--- | :--- | :--- | :--- |
| **XML Tag Injection** | Malicious `<tag>` strings in titles or descriptions | All elements escaped via `models.xml_escape()` with `&lt;` and `&gt;` | **SECURE** (Tested in `tests/test_stress_and_security.py`) |
| **XML Attribute Injection** | Quotes `"` or `'` in field names or group tags | Attributes enclosed in double quotes and escaped with `&quot;` | **SECURE** |
| **XML 1.0 Control Character Crash** | Non-printable ASCII bytes (`\x00`, `\x07`, `\x0c`) | Sanitized to escaped hex literals (`\\x00`) to prevent parser termination | **SECURE** |
| **Command Injection** | Shell metacharacters (`;`, `\|`, `$()`) in values | Values compiled into PCRE2 regex strings; no subprocess execution in backend | **SECURE** |
| **Unsafe Deserialization** | Arbitrary object execution via YAML tags | pySigma enforces `yaml.safe_load`; PyYAML dangerous tags rejected | **SECURE** |

### 1.2 Denial of Service & Resource Exhaustion (DoS / ReDoS)

1. **Cartesian Conjunction Explosion (Algorithmic DoS)**:
   - Transforming nested boolean conditions like `((A or B) and (C or D) and ...)` into Disjunctive Normal Form (DNF) produces $2^N$ clauses.
   - **Defense**: `MAX_DNF_DISJUNCTS = 256` is strictly enforced in `_cartesian_conjunction`. If an adversarial rule exceeds 256 clauses, conversion aborts immediately with `WazuhConversionError`.
2. **Extreme Payload Lengths**:
   - Compiling 10,000+ character strings or regexes does not cause recursion errors or stack overflows. Tested in automated stress suite.
3. **ID Allocator Space Exhaustion**:
   - If more rules are converted than available SIDs in the pool (`100000 - 120000`), the allocator raises typed `WazuhIDCollisionError` without infinite loops.

## 2. Reliability & Determinism

### 2.1 Conversion Determinism & Idempotency
- **Determinism**: Rule SIDs are generated by hashing the Sigma rule identifier (`rule.id` or `rule.title`) using SHA-256 with deterministic salt offsets for disjunctive branches.
- **Repeatability**: Repeated conversions of the same rule produce identical Wazuh XML byte-for-byte across runs.
- **State Isolation**: Backend state does not leak between conversions; `ConversionState` instances are scoped per-rule.
